kik는 한국어 문장을 Plan IR로 컴파일합니다. 날씨·캘린더 같은 도구는 기계적으로 호출하고, LLM은 판단과 최종 문장에만 씁니다. 일정 등록 같은 쓰기는 사람의 승인 뒤에만 일어납니다.

구성 보기 흐름 보기 
[send] POST /plans now=2026-10-23T09:03+09:00 location=강남구
[plan] if weather.good then calendar.create
[tool] weather.forecast 서울 · 2026-10-24T19:00
[judge] walk_ok=true coat_needed=true 0.86
[final] confirm: 산책 일정을 등록할까요?
[wait] 사람의 승인을 기다립니다
등록취소

무엇을 하나

문장 → 계획

mecab-ko 파서가 절·슬롯을 뽑고, 규칙이 seq·if·call·judge·final·confirm 노드로 컴파일합니다. LLM은 구조를 만들지 않습니다.

도구는 고정

어떤 도구를 어떤 순서로 부를지는 계획이 정합니다. 날씨는 기상청(KMA) 실측, 일정은 로컬 SQLite에서 읽고 씁니다.

쓰기는 승인 뒤

최종 답변은 얇은 JSON envelope입니다. 클라이언트는 표시·확인만 하고, 승인 전에는 쓰기 요청이 0회입니다. 같은 확인은 멱등입니다.

한 번의 요청, 하나의 흐름

  1. 1

    입력

    클라이언트가 현재 시각과 수동 위치를 함께 보냅니다. 위치는 한 번만 지오코딩해 좌표로 저장합니다.

  2. 2

    컴파일

    내일 저녁 같은 상대 시간을 KST 절대 시각으로 바꾸고, 빠진 슬롯이 있으면 실행 대신 ask로 되돌립니다.

  3. 3

    실행

    16k 컨텍스트에서 판단하고, 4k 컨텍스트에서 최종 문장을 만듭니다. 두 컨텍스트는 계획 사이에 재사용합니다.

  4. 4

    확인

    kind=confirm이면 등록/취소를 기다립니다. 슬롯이 겹치면 확인 대신 충돌을 알리는 답을 줍니다.

구성

kik-daemon

C++23 + llama.cpp. 모델·컨텍스트·KV·추론을 소유하고 유닉스 소켓으로만 말합니다.

kik-cli

데몬 소켓과 말하는 유일한 프로세스. 사람과 API가 쓰는 얇은 명령 클라이언트입니다.

kik-api

Node 26 + Fastify. /plans·도구 실행·타임라인 SQLite·확인 토큰을 소유합니다.

kik-parserd

mecab-ko 사이드카. 형태소·절 태그·슬롯만 돌려주고 실행은 하지 않습니다.

kik-client

Tauri 2 + Svelte 5. 프레임 없는 입력창, 로그, 결과 카드, 메뉴 막대 아이콘.

6.8–8.1초계획 1건
1lane 기본

계획 1건 = 날씨 1.7초 + 판단 2.2초 + 최종 3.5초. 파싱은 0.01초. lane을 2개로 늘리면 경합 때문에 tok/s가 11대로 떨어져 기본은 1개입니다.
