kik는 한국어 한 문장을 실행 가능한 계획으로 바꿉니다. 모델은 당신의 기기에서만 돌고, 도구는 계획이 고정하며, 쓰기는 당신의 손을 거칩니다.

  • 클라우드 없음
  • 도구 고정
  • 승인 후 쓰기
  • JSON envelope

왜 kik인가

클라우드가 없다

프롬프트도, 일정도, 대화도 밖으로 나가지 않습니다. 모델은 당신의 기기에서 돌고, 데이터는 당신의 디스크에 남습니다.

도구를 고르지 않는다

LLM은 어떤 도구를 부를지 고르지 않습니다. 계획이 정하고, 모델은 판단과 문장만 씁니다. 엉뚱한 API 호출이 끼어들 자리를 설계에서 지웠습니다.

쓰기는 사람이

일정 등록은 승인 뒤에 한 번. 같은 확인은 멱등입니다. 승인 전 쓰기는 0회. 자동화도 같은 규칙을 따릅니다.

한 번의 요청, 하나의 흐름

  1. 1

    입력

    클라이언트가 현재 시각과 수동 위치를 함께 보냅니다. 위치는 한 번만 지오코딩해 좌표로 저장합니다.

  2. 2

    컴파일

    내일 저녁 같은 상대 시간을 KST 절대 시각으로 바꾸고, 빠진 슬롯이 있으면 실행 대신 ask로 되돌립니다.

  3. 3

    실행

    16k 컨텍스트에서 판단하고, 4k 컨텍스트에서 최종 문장을 만듭니다. 두 컨텍스트는 계획 사이에 재사용합니다.

  4. 4

    확인

    kind=confirm이면 등록/취소를 기다립니다. 슬롯이 겹치면 확인 대신 충돌을 알리는 답을 줍니다.

구성

kik-daemon

C++23 + llama.cpp. 모델·컨텍스트·KV·추론을 소유하고 유닉스 소켓으로만 말합니다.

kik-cli

데몬 소켓과 말하는 유일한 프로세스. 사람과 API가 쓰는 얇은 명령 클라이언트입니다.

kik-api

Node 26 + Fastify. /plans·도구 실행·타임라인 SQLite·확인 토큰을 소유합니다.

kik-parserd

mecab-ko 사이드카. 형태소·절 태그·슬롯만 돌려주고 실행은 하지 않습니다.

kik-client

Tauri 2 + Svelte 5. 프레임 없는 입력창, 로그, 결과 카드, 메뉴 막대 아이콘.

측정 (p1, Qwen3-4B, CPU)

23.7judge tok/s
21.1final tok/s
6.8–8.1초계획 1건
1lane 기본

계획 1건 = 날씨 1.7초 + 판단 2.2초 + 최종 3.5초. 파싱은 0.01초. lane을 2개로 늘리면 경합 때문에 tok/s가 11대로 떨어져 기본은 1개입니다. 좋은 숫자만 고르지 않았습니다.

로컬에서, 계획대로.

모델은 기기 안에, 도구는 계획 안에, 쓰기는 당신 손에. kik는 그 세 가지를 분리하는 것에서 시작했습니다.
